# 本地化

支持简体中文（`zh-Hans`）、繁体中文（`zh-Hant`）、英语（`en`）和日语（`ja`）。
通用设置可选择跟随系统或指定语言，偏好保存在应用的 UserDefaults 中。
跟随系统按语言偏好顺序匹配，中文优先识别 Hans/Hant，其次识别 TW/HK/MO 地区；无匹配时使用英语。

应用自有界面即时更新，包括设置、菜单、窗口标题、导入选择、进度、确认与错误窗口。
切换只更新显示文案，保持现有 SwiftUI 视图身份，不重建模型控制器。
系统文件选择框等可能缓存进程语言；应用保存 AppleLanguages 偏好，重启后完整生效。

## 资源与调用

四套 `Resources/Localizations/*.lproj/Localizable.strings` 共用稳定语义 key。
目前每种语言 210 个 key。CMake 在签名前复制资源，资源变更会触发重新链接和签名。
新增文案必须同步更新四套资源，所选语言缺失的条目回退英语。

SwiftUI 与 AppKit 均通过 `L10n.text` 获取当前语言文案，不依赖 SwiftUI 对字符串字面量的隐式处理。
动态文案用 `{0}`、`{1}` 等位置参数；参数一次替换，作者内容中的花括号不再解释。
`L10n.count` 为当前数量文案选择单数 `.one` 或复数基础 key；四种语言各自提供完整模板。
`LanguageStore` 与 `appLanguageChanged` 通知分别驱动 SwiftUI 和 AppKit 刷新。

## 内容边界与持久化

作者提供的角色名、服装名、动作名、动作组、表情、用户改名、文件名、路径和显示器名保持原文。
仅程序生成的默认名称使用 `GeneratedName` 元数据，保存 key、参数与去重后缀；切换语言不改写模型资源。
旧设置或服装清单没有来源元数据时，名称一律按原文处理，不能凭“默认”等文字猜测来源。
用户改名后清除生成名称元数据。新增元数据可由旧格式读取路径忽略，不改变既有模型 ID 或动作权重 key。

校验与导入错误使用 `LocalizedFailure` / `LocalizedMessage` 保留模板、原始参数与底层异常。
缓存错误和警告在展示时翻译，不需要重新导入或加载模型。
原生桥接错误通过 NSError 的 `Lite2DLocalizationKey` 传递稳定身份。
未知系统、第三方错误显示本地化说明并保留原始技术详情。
角色状态和设置页使用独立枚举身份，业务判断不比较翻译后的字符串。

开发日志、自测输出、项目文档不在四语翻译范围。

## 验证

```sh
python3 scripts/test_localization.py
python3 scripts/test_model_import.py
sh scripts/build.sh
python3 scripts/run_integration.py
```

专项测试校验四语 key、占位符、语言匹配、偏好保存、单复数、英语回退、缓存错误及作者名称兼容。
导入测试按错误身份断言，不依赖某种语言的错误文字。
应用内集成测试切换四种语言，检查现有窗口和菜单、设置页与角色选择、模型设置和控制器身份，并生成 16 张设置页截图。
测试使用独立偏好域，避免修改正常使用时的语言选择。
