# 实机交互验收

这些项目需要真实桌面交互或本机当前没有的硬件。应用内测试不能证明实际 Finder、Space、Stage Manager 和拔屏行为。用户要求不使用 Computer Use，开发过程不会发送系统鼠标/键盘事件、自动操作其他应用或更改显示设置。

当前自动验证范围见 TEST_REPORT.md。以下步骤为剩余实机验收的可重复操作；未执行前保持“未验证”。

| 场景 | 操作 | 通过条件 | 当前状态 |
|---|---|---|---|
| F05 穿透 | 显示至少三个角色，全部结束编辑，拖动角色下方 Finder 文件/窗口，再移动鼠标 | Finder 操作成功，角色仍分别跟踪鼠标 | 未验证实际 Finder 交互 |
| F06 拖动和滚轮 | 菜单选择 A 编辑，拖动 A 并滚轮缩放，确认 B/C 继续动画；转为 B 编辑 | 只有选中角色可拖动，其他角色继续穿透；A/B 状态互不覆盖 | 管理器编辑/缩放已自动测，实际设备输入未验证 |
| F07 三屏 | 在三块屏幕间移动鼠标，分别把角色拖到左侧/主屏/右侧内屏，观察头部与眼球 | 左右上下方向一致，位于负屏幕坐标的角色无反转；各角色根据自己位置计算目标 | 三屏坐标变换和合成目标已测，实际光标轨迹未验证 |
| F08 不同 DPI | 把 A 在 Retina 与 1× 显示器间移动，观察窗口 point 尺寸和纹理清晰度 | 角色比例合理，backing viewport 跟随像素尺寸，无裁切/黑底 | 本机三屏均 2×；1× 硬件未提供 |
| F09 拔屏 | 先保存外接屏上的角色布局，断开显示器，再连接 | 窗口自动回到可见区域，或可通过菜单“重置位置”找回 | 自动恢复逻辑待断接硬件实测 |
| F14 Space | 显示三个角色，切换桌面 Space 和全屏应用，测试 Stage Manager 开/关 | 记录实际可见性；菜单栏始终能隐藏/恢复/重置角色；无假定强制全屏置顶 | 采用 floating / canJoinAllSpaces / fullScreenAuxiliary，系统场景未实测 |

执行时记录系统版本、显示器、实例 UUID 短码及观察结果；只向报告添加实际完成的结果。若系统无法在特定全屏/Space 场景显示角色，应明确保留限制，不为此申请辅助功能或屏幕录制权限。

## 独立手测会话

`python3 scripts/launch_manual.py` 会启动独立 bundle 标识的本机副本，使用 `.local/verification/manual/settings.json`，默认显示“手测 1/2/3”三个实例。它只启动本应用，不自动化键盘/鼠标输入。退出通过该会话菜单，测试结果可直接回复，由开发过程合并报告。性能基线会话中的实例以 `baseline-` 开头，请勿修改其配置。

手测副本来源于当前已经通过集成验证的构建；后续若交互实现发生变化，须重新核实受影响项目。物理拔屏测试前先保存其他应用工作，按用户自己的实际环境决定测试时机。
